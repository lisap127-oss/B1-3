## 프로젝트 개요  

본 프로젝트는 노코드 자동화 도구(Make, Zapier)를 직접 사용하여    
동일한 워크플로우를 비교 구현하고, 자유 주제 자동화를 설계 및 구현한 결과물입니다.

## 프로젝트 1: 자동화 도구 비교 구현  

### 1-1. 구현 개요  

| 항목 | 내용 |
|------|------|
| 사용 도구 | Make, Zapier |
| 트리거 | Google Sheets – 새 행 감지 |
| 분기 조건 | 참가 가능 / 참가 불가 |
| 액션 | Gmail – 경로별 맞춤 이메일 발송 |

### 1-2. 워크플로우 구조  
Google Sheets (New Row)   
          ↓  
Router / Split into Paths  
   ↙              ↘  
Path A           Path B  
(참가 가능)    (참가 불가 및 대기)  
    ↓               ↓  
Gmail 발송       Gmail 발송  
(확정 이메일)  (불가 및 대기 이메일)  


### 1-3. 동일성 설계 기준  

두 도구에서 아래 4가지 요소를 동일하게 맞춰 구현했습니다.  

| 요소 | 기준 |
|------|------|
| 입력 이벤트 | Google Sheets 동일 시트, 동일 열 구조 사용 |
| 핵심 Action | Gmail 이메일 발송 (제목/본문 동일) |
| 분기 조건 | 참가여부 열 값 기준 동일 조건 적용 |
| 최종 출력 | 각 경로별 이메일 1건 발송 |

### 1-4. 비교 분석 보고서  

#### 사용 도구  
- **Make**    
- **Zapier**  

#### 구현 과정 요약  

**Make**  
1. Google Sheets – Watch Rows 모듈 설정  
2. Router 모듈 추가 → 2개 경로 분기  
3. 각 경로에 Filter 조건 설정 (참가 가능 / 불가)  
4. 각 경로에 Gmail – Send an Email 모듈 연결  
5. 시나리오 실행 및 테스트 완료  

**Zapier**  
1. Google Sheets – New Spreadsheet Row 트리거 설정  
2. Paths – Split into Paths 추가 → Path A / Path B 구성  
3. 각 Path에 조건(Path conditions) 설정  
4. 각 Path에 Gmail – Send Email 액션 연결  
5. 각 단계 테스트 및 Publish 완료  

#### 비교 항목 (5개 이상)

| 비교 항목 | Make | Zapier |
|-----------|------|--------|
| **UI/UX** | 캔버스 기반 시각적 흐름, 직관적인 모듈 연결 | 단계별 리스트 형태, 선형 구조로 단순함 |
| **설정 난이도** | 초기 진입 시 용어가 생소하나 분기 설정이 유연함 | 단계별 가이드가 친절하여 초보자 접근성 높음 |
| **조건 분기 방식** | Router 모듈로 다중 경로 시각적 분기 가능 | Paths 기능으로 분기 가능하나 시각적 직관성 낮음 |
| **연동 서비스 범위** | 1,000개 이상 앱 연동 지원 | 6,000개 이상 앱 연동 지원 (더 넓음) |
| **무료 플랜 범위** | 월 1,000 Ops / 시나리오 수 제한 없음 | 월 100 Task / Zap 5개 제한 |
| **실행 로그 확인** | 시나리오별 실행 이력 상세 확인 가능 | Zap History에서 단계별 결과 확인 가능 |
| **에러 처리** | 모듈별 오류 핸들러 설정 가능 | 기본 재시도 제공, 세부 설정 제한적 |

#### 각 도구의 장단점  

**Make**  
| 장점 | 단점 |
|------|------|
| 시각적 분기 구조가 직관적 | 초기 학습 곡선 존재 |
| 무료 플랜에서 복잡한 워크플로우 구현 가능 | 영어 중심 문서 |
| 세밀한 조건/필터 설정 가능 | 연동 앱 수가 Zapier보다 적음 |

**Zapier**  
| 장점 | 단점 |
|------|------|
| 단계별 설정 가이드로 초보자 친화적 | 무료 플랜 Task 수 제한이 빡빡함 |
| 연동 앱 수가 가장 많음 | 복잡한 분기 설계 시 직관성 떨어짐 |
| 안정적인 서비스 운영 | 고급 기능은 유료 플랜 필요 |

#### 도구 선택 적합 상황  

| 상황 | 추천 도구 |
|------|-----------|
| 복잡한 분기/조건 로직이 필요한 경우 | **Make** |
| 빠르게 간단한 자동화를 만들고 싶은 경우 | **Zapier** |
| 무료로 많은 실행 횟수가 필요한 경우 | **Make** |
| 다양한 SaaS 앱과 연동이 필요한 경우 | **Zapier** |
| 팀 협업/운영 자동화 고도화 | **Make** |

## 프로젝트 2: 행사 신청 자동화 고도화  

### 2-1. 반복 업무 정의  

Google Form으로 행사 신청이 들어오면,  
참가 여부에 따라 확인 이메일을 자동 발송하고  
신청 내역을 별도 시트에 자동으로 기록하는 작업  

> 기존에는 신청 내역을 수동으로 확인하고 이메일을 일일이 발송해야 했으나,  
> 자동화를 통해 수동 개입 없이 처리 가능  

### 2-2. 도구 선정 및 이유  

**선정 도구: Make**  

| 선정 이유 | 설명 |
|-----------|------|
| 시각적 분기 직관성 | Router를 통해 참가 가능/불가 경로를 캔버스에서 한눈에 파악 가능 |
| 무료 플랜 범위 | 월 1,000 Ops 내에서 Trigger + Router + Gmail 2개 + Sheets 기록까지 구현 가능 |
| 프로젝트 1 비교 결과 반영 | 복잡한 분기 로직에서 Make가 더 적합하다고 판단 |

### 2-3. 워크플로우 설계  

#### 흐름도  
          [Trigger]  
   Google Sheets – Watch Rows  
         (새 신청 행 감지)  
                ↓  
              [분기]  
              Router  
             ↙      ↘  
          Path A    Path B  
 참가여부 = "가능"   참가여부 = "불가 및 대기"  
       ↓                  ↓  
  [Action 1]          [Action 1]  
    Gmail                Gmail  
 참가 확정 이메일    참가 불가 및 대기 이메일  
      ↓                     ↓  
  [Action 2]            [Action 2]  
 Google Sheets          Google Sheets    
 이력 시트 기록           이력 시트 기록  


#### 단계별 입력/출력  

| 단계 | 모듈 | 입력 | 출력 |
|------|------|------|------|
| 1 | Google Sheets Watch Rows | 새 행 추가 이벤트 | 이름, 이메일, 참가여부 데이터 |
| 2 | Router | 참가여부 값 | Path A 또는 Path B 경로 선택 |
| 3-A | Gmail (Path A) | 이름, 이메일 | 참가 확정 이메일 발송 |
| 3-B | Gmail (Path B) | 이름, 이메일 | 참가 불가 이메일 발송 |
| 4 | Google Sheets Add Row | 이름, 이메일, 참가여부, 처리시각 | 이력 시트에 행 추가 |

#### 조건 분기 설계 기준  

| 경로 | 조건 | 처리 |
|------|------|------|
| Path A | 참가여부 열 값 = `"가능"` | 참가 확정 이메일 발송 |
| Path B | 참가여부 열 값 = `"불가"` | 참가 불가 이메일 발송 |

> 조건 기준: Google Sheets의 `참가여부` 열 텍스트 값으로 분기  
> 두 경로 모두 이력 기록 Action 포함 (공통 처리)

> 첨부 파일: Make루트.png  

### 2-5. 실행 결과 화면
> 첨부 파일: 설문참여 폼.png, 스프레드 시트 이력.png, 참가 가능.png, 참가 불가 및 대기.png

## 핵심 개념 정리  

### Trigger vs Action  

| 구분 | 설명 | 예시 |
|------|------|------|
| **Trigger** | 자동화를 시작시키는 이벤트. 외부에서 발생하는 신호를 감지 | Google Sheets에 새 행이 추가됨 |
| **Action** | Trigger 이후 자동으로 수행되는 처리 작업 | Gmail로 이메일 발송, Sheets에 행 추가 |

> Trigger가 "시작점"인 이유:  
> 자동화는 항상 특정 이벤트가 발생해야 실행됩니다.  
> Trigger 없이는 언제 실행할지 알 수 없으므로, 모든 워크플로우의 출발점이 됩니다.  

### 조건 분기 (Filter/Router)  

- **역할**: 데이터 값에 따라 서로 다른 처리 경로로 흐름을 나누는 역할  
- **본 프로젝트 적용**: 참가여부 값에 따라 이메일 내용을 다르게 발송

## 심층 분석  

### Q1. 트리거 불안정 / 외부 연동 실패 시 대응 방안  

| 대응 방식 | 설명 |
|-----------|------|
| **모니터링** | Make 실행 이력(History)에서 실패 시나리오 즉시 확인 |
| **재시도 설정** | Make의 오류 핸들러(Error Handler) 모듈로 자동 재시도 구성 |
| **대체 경로** | 오류 발생 시 관리자에게 알림 이메일 발송하는 별도 경로 추가 |
| **Webhook 대체** | Google Sheets 트리거가 불안정할 경우 Webhook 방식으로 전환 고려 |

### Q2. 조건 분기가 늘어날 경우 구조화 방안  

| 방안 | 설명 |
|------|------|
| **Router 경로 추가** | Make Router는 다중 경로(3개 이상)를 지원하므로 조건별 경로 확장 |
| **모듈화** | 공통 처리(이력 기록 등)는 별도 시나리오로 분리 후 호출 |
| **조건 우선순위 정의** | 분기 조건 간 충돌 방지를 위해 우선순위 명시 |
| **문서화** | 분기 조건이 복잡해질수록 설계 문서(플로우차트)를 병행 관리 |

## 제약 사항 준수 내역  

### 무중단(Continuous) 실행 입증  

Make는 기본적으로 **Scheduling(스케줄링)** 기능을 통해   
시나리오가 지속적으로 실행되도록 설정할 수 있습니다.  

#### 무중단 실행 설정 방식  

| 항목 | 설정 내용 |
|------|-----------|
| 실행 방식 | Scheduling ON – 일정 간격으로 자동 반복 실행 |
| 실행 주기 | 15분 간격 (무료 플랜 최소 단위) |
| Watch Rows 방식 | 마지막으로 읽은 행 이후 새 행만 감지 (중복 처리 없음) |

#### 연속 트리거 처리 로그  

> 첨부파일: Make History.png 
> → 복수의 실행 기록(시각, 처리 건수, 성공 여부)이 확인되는 화면

아래는 실행 로그 예시 구조입니다.  

| 실행 시각 | 처리 건수 | 상태 |
|-----------|-----------|------|
| 2025-xx-xx 10:00 | 1건 (Path A – 참가 가능) | ✅ 성공 |
| 2025-xx-xx 10:15 | 1건 (Path B – 참가 불가) | ✅ 성공 |
| 2025-xx-xx 10:30 | 0건 (신규 행 없음) | ✅ 정상 대기 |

> 위 로그를 통해 Trigger 발생 시 수동 개입 없이  
> 자동으로 반복 실행되고 있음을 확인할 수 있습니다.

### 민감정보 비노출 확인  

#### 검토 항목 및 처리 내역  

| 항목 | 처리 방법 | 확인 결과 |
|------|-----------|-----------|
| Google 계정 이메일 | 스크린샷 내 이메일 일부 마스킹 처리 (예: `ab***@gmail.com`) | ✅ 노출 없음 |
| Gmail 연동 토큰 | Make 내부 처리, 화면에 표시되지 않음 | ✅ 노출 없음 |
| Google Sheets API 키 | OAuth 방식 연동으로 Key 직접 입력 없음 | ✅ 노출 없음 |
| Make 시나리오 공유 링크 | 미사용 (스크린샷으로만 제출) | ✅ 노출 없음 |
| 기타 비밀번호/토큰 | 해당 없음 | ✅ 노출 없음 |

#### 확인 방법  

- 제출 스크린샷 전체를 육안 검토하여 민감정보 노출 여부 확인  
- Make의 Google 연동은 **OAuth 2.0 방식**을 사용하므로  
  API Key나 토큰이 화면에 직접 표시되지 않는 구조  
- 계정 이메일이 포함된 화면은 **마스킹 처리 후 첨부**  

> ✅ 본 제출물(스크린샷, README.md)에는  
> API Key, 토큰, 비밀번호 등 민감정보가 포함되어 있지 않음을 확인합니다.
